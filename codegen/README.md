# OpenHydroQual — Model Compiler (codegen)

Generates a **standalone, hard-coded C++ solver library** for a *specific* loaded
model. All equations are lowered to straight-line C++ — **no expression
interpreter at runtime** — and the result links only against a tiny header-only
runtime (no Qt, no armadillo), so it embeds into any program. The generated
class exposes a **one-step / run-to-time** API for external callers.

Everything codegen-related lives in this folder.

## Why

The interpreter's cost is concentrated in residual/Jacobian evaluation
(`System::GetResiduals` re-walks `Expression::calc` every Newton iteration). A
model's computational shape is *static after load*, so those formulas can be
compiled once into specialized code. Expected 5–50× per-evaluation speedups —
the win lands squarely in the repeated-solve loops (`GA/`, `MCMC/`, calibration).

## Layout

```
codegen/
  runtime/          # header-only, dependency-free — GENERATED models link ONLY this
    ohq_intrinsics.h   # _exp _log _abs _sgn _sqr _sqt _pos _hsd _min _max
                       # _mon _mbs _lpw _ups _bkw + '^' (exact Expression::func parity)
    ohq_timeseries.h   # interpol + ekr/gkr kernels (parity with TimeSeries.hpp)
    ohq_linalg.h       # small dense Newton linear solve (swap-in point for sparse)
    ohq_solver.h       # templated damped-Newton + adaptive dt; step()/runTo() API
  include/          # the generator (links OHQ core)
    ExpressionEmitter.h    # Expression tree -> C++ string           [DONE]
    DependencyAnalyzer.h   # quantity tiering (constant/per-step/per-iter) [design]
    CodeGenerator.h        # System -> <Class>.h/.cpp                 [design]
  src/
    ExpressionEmitter.cpp  # [DONE, tested]
  demo/
    two_pond_model.h       # hand-written TARGET model (what the generator emits)
    main_two_pond.cpp      # embeds it via the external step()/runTo() API
  tests/
    test_emitter.cpp       # live emitter tests against real Expression trees
  CMakeLists.txt
```

## Design: extreme efficiency via quantity tiering

Every quantity is classified by a static dependency analysis and lowered to the
coarsest loop level where it stays valid:

| Tier | Depends on | Emitted as | Example |
|------|-----------|-----------|---------|
| Constant | neither state nor time | folded literal | `area`, `lambda`, `mu`, `ratio` |
| Per-step | time / time-series only | computed once per step | `kernel_smoothed_forcast`, `valve_K` |
| Per-iteration | a state variable | local in `residual()` | `max_flow`, `flow`, storage balance |

State (`balance`) variables live in a flat array addressed by index enums;
per-iteration intermediates are register locals; the analytical Jacobian is
generated by differentiating the same expression trees (fixed CSR sparsity).

## Status

- **Runtime** — complete, compiles clean, dependency-free.
- **Emitter** — complete and **tested** (precedence, `^`→`ohq::powr`, all
  intrinsics, `_ekr`/`_gkr` series handles, and the exact `precipitation_forcast.json`
  uncertain-forecast expression). 8/8 tests pass.
- **Target model + solver** — `two_pond_demo` converges to the analytical steady
  state (error ~3e-6), exercising `step()` / `runTo()`.
- **DependencyAnalyzer** — implemented: builds the quantity graph from
  `Expression` refs + `Quan` types, propagates state/time labels to a fixed
  point, assigns tiers, and folds constants.
- **CodeGenerator** — implemented (v1): walks blocks/links, emits state enum,
  folded constants, per-step precompute, per-iteration residual, numerical
  Jacobian, and the `initialize/step/runTo/time` API into `<Class>.h`.
- **`ohq_generate` CLI** — loads a real `.ohq` model (via libOHQLib) and emits
  the header. **Validated end-to-end** on `Examples/Parallel_Links`: 3 blocks /
  4 links → generated C++ that **compiles and links** against the runtime, with
  the correct residual/flux structure and fixed flows folded to literals while
  timeseries inflows are per-step.

### Correctness pass (done)
- **Per-iteration topological ordering** — per-iteration locals are now emitted
  in dependency order (Kahn sort over the analyzer's edges), fixing
  use-before-declaration (e.g. `depth` before `area`).
- **Initial-value expressions** — `calcinivalue()` initial expressions are
  translated and emitted in `initialValues()`.
- **Time-series baking** — a quantity's loaded data points are baked inline
  (≤50k points) so the generated library is self-contained; larger series fall
  back to the `set_ts_*()` setter.
- **Parity harness** (`tests/parity_harness.cpp`, `tests/run_parity.sh`) — runs
  the interpreter (`System::Solve`) and the generated model to the same `tend`
  and diffs per-block state.

### Outflow limiting (`applylimit`) — done
The mass-balance runtime (`runtime/ohq_massbalance.h`) reproduces the
interpreter's `applylimit` complementarity: a block that would go negative flips
to "limited" mode — storage pinned to `past*landtozero` (~0) and its state
unknown becomes an outflow factor in [0,1] that drains it exactly to empty — with
the flag propagating through rigid neighbours and an outer switching loop that
re-solves until the limited set is stable (mirrors `System::OneStepSolve`). The
generated model supplies only the model-specific parts: topology
(`linkSrc/linkDst`), `rigid[]` flags, `computeFluxes()` (raw link flows + own
inflows over effective storage), and `initialStorage()`.

### Parity status (verified by `tests/parity_harness.cpp`)
Compared at the interpreter's actual final time (its outer loop runs while
`t < tend + dt`, overshooting `tend` by up to one step):

| model | what it exercises | max rel err |
|-------|-------------------|-------------|
| `Parallel_Links` | fixed flows, no limiting | 2.6e-4 (residual is end-of-run time rounding: interpreter state at t≈5.194 vs reported 5.198) |
| `Draining_Tank`  | a tank drained to empty → **limiting engages** | **6.5e-15 (machine precision)** |

Time scheme matches the interpreter (`c_n_weight = 1`, fully implicit).

### Limitations (next up, priority order)
- **Rules** (`Quan::_type::rule`) rejected with a clear error (need `Condition`
  introspection).
- **Transport / constituents** not emitted (constituent mass states like
  `DOM_mass`); flow-only models work. Surfaced by `Examples/Wet_pond`.
- **Analytical Jacobian** — numerical FD for now; AD over the trees is the
  planned optimization.

## Build & test

```bash
cmake -S codegen -B codegen/build -DCMAKE_PREFIX_PATH=/usr/lib/x86_64-linux-gnu/cmake
cmake --build codegen/build -j
(cd codegen/build && ctest --output-on-failure)   # emitter tests
./codegen/build/two_pond_demo                      # runtime end-to-end demo
```

The generator target needs the OHQ core: `libOHQLib.so` (set `-DOHQLIB_DIR=...`)
and Qt6. Generated model libraries need none of that — only `codegen/runtime/`.
